## 5. P0：必须优先修复（已全部修复）

### P0-01 关键公开事实没有进入长期事实（已修复）

#### 已确认现象

- 第 1 轮警长投票后，5 号和 8 号平票。
- 5 号在 PK 发言中明确说：“我 5 号，预言家。昨晚验了 6 号，6 号是好人。”
- 1 号是在该段 PK 发言之后才自爆。
- 最终 `public_facts` 保存了普通警上发言，却没有保存这段 PK 发言。
- 第 4 轮 10、11、12 号均把 5 号描述成“第四轮突然跳预言家”。

#### 影响

- 对局最重要的身份声明被历史系统遗忘。
- 真预言家被迫为“没有早跳”辩护，而实际上已经早跳。
- 狼人不需要主动伪造完整逻辑，只需利用系统遗忘形成错误共识。
- 回放中的最终票型虽然数据合法，但决策基础不公平。

#### 根因判断

高概率涉及以下问题：

1. 普通 `sheriff_speech` 会写入公开事实，而 `sheriff_pk_speech` 只进入轮次状态或动作日志，没有进入长期公开事实。
2. 玩家是无持久记忆的模型实例，自身先前发言如果没有重新注入 Prompt，也会被自己遗忘。
3. 公开事实压缩按时间裁剪，身份声明、PK 发言等高价值事实没有受到保护。

#### 修改方向

1. 将下列信息写入结构化公开事实，而不是只保存自由文本：
   - 普通警上发言；
   - PK 发言；
   - 明确身份声明；
   - 验人、金水、查杀等公开结果声明；
   - 退水、最终候选、警长票型和 PK 票型；
   - 自爆前最后完成的发言阶段。
2. 为公开事实增加稳定字段，例如：
   - `fact_type`；
   - `round_number`；
   - `phase`；
   - `actor`；
   - `claim_role`；
   - `claim_target`；
   - `claim_result`；
   - `source_event_id`。
3. Prompt 组装时对以下事实设置不可裁剪或较高保留优先级：
   - 身份声明；
   - 验人结果声明；
   - 死亡、自爆、放逐；
   - 警长当选或警徽流失；
   - 当前仍影响判断的历史票型。
4. 单独保存每名玩家的“公开自我历史”，保证角色至少能回忆自己曾经公开说过什么。
5. 对与结构化事实明显冲突的发言增加质量校验。第一阶段可先记录告警；稳定后再对确定性矛盾执行带反馈重试。

#### 建议涉及模块

- `apps/api/app/werewolf/engine.py`
- `apps/api/app/werewolf/public_facts.py`
- `apps/api/app/werewolf/prompts_zh.py`
- `apps/api/app/werewolf/quality_evaluation.py`

#### 验收标准

- 第 1 轮 PK 发言在第 4 轮任意玩家 Prompt 中仍可检索。
- 5 号自己的后续 Prompt 明确包含“自己第 1 轮已跳预言家并报 6 号好人”。
- 新增自动化测试覆盖 `sheriff_pk_speech -> public fact -> later round prompt` 全链路。
- 压缩公开事实后，身份声明和验人声明不得被普通模板发言挤出。

### P0-02 中断阶段没有表达“未获得发言机会”（已修复）

#### 已确认现象

- 第 3 轮发言顺序中，9 号在轮到 5 号之前自爆。
- 5 号第 3 轮没有完成任何警上发言。
- 第 4 轮 10、11、12 号都将其解释为“5 号第三轮竞选时没有跳预言家”。
- 7 号多轮没有公开发言，也主要由自爆中断和其警下位置导致，但女巫把“始终未发言”作为毒杀依据。

#### 影响

- “没有机会发言”被错误理解为“有机会但选择沉默”。
- 自爆不仅按规则终止白天，还会额外制造并不存在的行为污点。
- 玩家会系统性怀疑后置位玩家，座位和发言顺序变成不合理的隐性惩罚。

#### 修改方向

1. 每个被中断的公开阶段保存结构化结束原因：
   - `interrupted_by=self_explosion`；
   - `last_completed_speaker`；
   - `pending_speakers`；
   - `stage= sheriff_speech / pk_speech / debate / vote`。
2. 在后续 Prompt 中明确区分：
   - 已发言；
   - 主动放弃或退水；
   - 因自爆未轮到；
   - 因死亡不再拥有发言机会。
3. 对“某玩家上一轮没发言”的推理增加事实提示：若属于流程中断，直接写明“该玩家未获得发言机会，不能据此单独形成狼面”。
4. 质量评估增加 `interruption_misattributed_as_silence` 类问题。

#### 验收标准

- 第 3 轮自爆后的事实中明确列出 5 号尚未发言。
- 第 4 轮 Prompt 不再把 5 号标记为“已发言但未跳身份”。
- 构造不同座位、不同自爆时点的测试，确保所有待发言玩家都被正确记录。

### P0-03 私密总结被公开输出（已修复）

#### 已确认现象

- 轮次状态将角色总结保存为 `private_summaries`。
- 流式事件却把 `summarize` 作为公开字段处理，相关 `model_response_delta` 标记为 `is_public=true`。
- 11 号狼人公开输出：“我选择夜晚刀 10 号玩家，明天与 12 号玩家周旋，声称 10 是最后一狼……”

#### 影响

- 直接泄露角色身份、阵营策略和下一步夜间行动。
- 即使对局尚未结束，也会彻底破坏公平性。
- Live 文本、字幕、语音、回放或持久化记录都可能成为泄密通道。

#### 修改方向

1. 将 `summarize` 从公开流字段映射、公开发言集合和公开语音集合中移除。
2. 更清晰地拆分两个概念：
   - `private_round_memory`：只提供给对应角色后续 Prompt；
   - `public_round_brief`：由服务端根据结构化状态生成，不调用带私有身份知识的模型。
3. Live 事件中不得发布私密总结原文；如运营调试确有需要，只能进入受权限保护的 debug 数据，且不得进入 C 端接口。
4. 回放数据、语音落库和 Admin 普通详情都应继续执行相同的私密字段边界。

#### 建议涉及模块

- `apps/api/app/werewolf/streaming.py`
- `apps/api/app/werewolf/voice.py`
- `apps/api/app/werewolf/engine.py`
- Live/Replay API DTO 与相关测试

#### 验收标准

- `summarize` 相关模型增量不再产生 `is_public=true` 事件。
- 不再生成 `speaker_kind=player` 的总结语音。
- C 端事件、回放和字幕中搜索“夜晚刀”“我是狼人”“狼人队友”等私密表达均无结果。
- 增加负向安全测试：狼人私密总结包含明确身份和刀人计划时，公开事件仍不得出现原文。

### P0-04 决胜动作后没有立即判定终局（已修复）

#### 已确认现象

- 第 4 轮 5 号预言家被放逐后，神职边立即全灭。
- 系统没有立刻发布 `game_completed`，而是继续让 10、11、12 号依次总结。
- 从放逐状态更新到 `game_completed` 间隔约 64 秒。
- 三名玩家都讨论了“如果 5 是好人，明天再盘”，但规则上已经不存在下一天。

#### 影响

- 产生逻辑上不存在的下一夜和下一轮计划。
- 延迟终局反馈，放大总结泄密风险。
- 终局等待看起来像系统卡顿或比赛仍在继续。

#### 修改方向

1. 在所有可能改变存活阵营的动作之后立即检查胜负：
   - 夜间死亡结算；
   - 女巫毒杀；
   - 猎人开枪；
   - 狼人自爆；
   - 白天放逐；
   - 白痴翻牌后的状态变化。
2. 一旦满足终局条件：
   - 停止后续玩家行动请求；
   - 发布最终状态；
   - 发布 `game_completed`；
   - 只生成服务端公开终局摘要。
3. 如果产品仍希望保留“赛后感言”，应将其定义为游戏结束后的独立展示阶段，不再影响游戏状态，也不得使用角色仍在行动的 Prompt。

#### 验收标准

- 最后一名神职或最后一名平民出局后，不再创建任何夜间行动、投票或私密回合总结请求。
- 决胜状态更新与 `game_completed` 的服务端间隔达到建议目标：小于 1 秒，不含客户端动画时间。
- 回归测试覆盖猎人开枪导致终局、自爆导致终局、女巫双死导致终局等组合场景。

## 6. P1：流程与观战正确性（已全部修复）

### P1-01 关键状态没有发布为 Live 事件（已修复）

#### 已确认现象

- 第 4 轮所有存活玩家均选择上警。
- 11、12 号退水后，最终候选为 5、10 号，但原始警下玩家为空。
- 引擎最终状态记录“警下无人可投票，警徽流失”。
- Live 事件中没有对应的状态更新，公开事实中也没有该结果。

#### 影响

- 观众看到警长竞选突然消失，直接进入普通发言。
- 前端无法可靠清空警徽状态或展示流失原因。
- 法官语音没有数据来源，回放也无法重建该转折。

#### 修改方向

1. 所有警长终态都必须发布结构化状态事件：
   - 当选；
   - 无人上警；
   - 全部退水；
   - 无警下玩家可投票；
   - 首轮无人得票；
   - 二轮仍未产生唯一领先者；
   - 自爆导致竞选延期或警徽流失。
2. 事件至少包含：最终候选、投票者、票型、是否流失、流失原因、当前警长。
3. 前端和语音只消费结构化终态，不从缺失字段推断。

#### 验收标准

- “警下无人可投票”产生唯一且可回放的状态事件。
- God View、事件时间线、法官语音和最终回放对警徽状态显示一致。
- 前端收到 `sheriff_badge_lost=true` 后，当前警长必须清空。

### P1-02 法官台词缺少关键流程和因果（已修复）

#### 已确认现象

- 第一夜女巫自救成功，但法官仅说“天亮了”，没有说“昨夜平安夜”。
- 第一轮警长平票后，没有清楚播报“进入 PK”。
- 三次自爆只播报“X 号发动狼人自爆”，没有说明该玩家出局、白天终止并直接进入夜晚。
- 第 4 轮猎人开枪没有“猎人发动技能”和选择目标的法官语音；天亮时直接同时宣布 4、3 号死亡。
- 警徽流失和最终狼人获胜在本局持久化语音中缺失。

#### 修改方向

1. 使用“流程事件 -> 法官台词序列”，不要让一个状态更新只能返回一条台词。
2. 补齐以下台词链：
   - 女巫救人成功 -> 平安夜；
   - 警长首轮平票 -> PK 发言 -> 二轮投票；
   - 自爆 -> 身份公开 -> 玩家出局 -> 白天终止 -> 进入夜晚；
   - 猎人死亡 -> 发动技能 -> 选择目标 -> 目标出局；
   - 警下无人 -> 警徽流失；
   - 放逐结果 -> 胜负检查 -> 获胜阵营。
3. 将死亡结果拆成有因果的结构化事件，避免在一个 `night_deaths` 列表中混合狼刀、毒杀和猎人枪杀而不解释来源。
4. 女巫救人导致零死亡时，平安夜判断应同时识别 `saved_by_witch`，不能只识别守卫保护。

#### 验收标准

- 第一夜自救的回放明确播报“昨夜平安夜”。
- 猎人枪杀目标时，字幕和语音先说明猎人触发，再说明目标出局。
- 自爆后在进入夜晚前，至少有一条明确的“本轮发言和投票终止”播报。
- 每种警长竞选终态均有独立法官台词测试。

### P1-03 终局语音尾段不完整（已修复）

#### 已确认现象

- 本局共持久化 107 条语音：79 条法官、28 条玩家。
- 玩家语音最后覆盖到 12 号最终辩论，法官语音最后覆盖到“12 号玩家请发言”。
- 此后仍有投票阶段、放逐结果、总结和 `game_completed` 事件，但没有相应持久化语音。

#### 根因判断

需要重点核验：

1. Live 语音是否依赖前端 WebSocket 持续在线才落库；
2. 客户端断开、重连或快速追帧时，是否把未播放事件当作上下文直接跳过；
3. 终局事件到达时，语音流是否在处理完队列前提前关闭；
4. 回放是否只依赖已落库语音，而没有根据完整事件补齐静态法官语音。

#### 修改方向

1. 将“用于历史回放的语音持久化”与“当前客户端是否连接”解耦。
2. 至少保证静态法官语音可由持久化事件确定性重建。
3. 终局关闭语音流前，等待已接受的语音任务完成或写入可恢复队列。
4. 保存并监控每局最大 `voice.last_source_event_id` 与 `live_events.max(event_id)` 的差值。

#### 验收标准

- 即使客户端在最终投票前断开，回放仍包含投票开始、放逐结果和获胜阵营法官语音。
- `game_completed` 对应的法官语音必须可回放。
- 语音补齐过程幂等，不产生重复终局台词。

### P1-04 Prompt 缺少行动资格和终局压力（已修复）

#### 已确认现象

- 第 4 轮四名存活玩家全部上警，没有警下玩家。
- 10 号仍说“警下玩家请慎重投票”。
- 12 号退水后仍说“警徽我投给 10 号”，但当前规则下退水者不属于原始警下投票者。
- 多名玩家在屠边残局中说“如果 5 是真预言家，明天再盘”，没有意识到放逐最后神职会立即结束游戏。

#### 修改方向

1. 在警长发言 Prompt 中明确提供：
   - 原始上警名单；
   - 原始警下名单；
   - 当前是否存在合法投票者；
   - 自己退水后是否有投票权。
2. 在残局 Prompt 中提供规则层面的压力提示，不泄露隐藏身份：
   - 当前存活人数；
   - 已公开狼人数量；
   - 本轮错误放逐可能触发屠神或屠民终局；
   - 不应默认一定存在下一轮。
3. 对“向不存在的投票者喊话”“声称执行无资格动作”增加质量告警和重试反馈。

#### 验收标准

- `sheriff_voters=[]` 时，Prompt 明确写明“本轮没有警下投票者”。
- 角色不得生成“我会投警徽”之类不可执行承诺。
- 屠边残局发言会明确表达“本轮可能直接决定胜负”，而不是无条件讨论明天。

### P1-05 连续自爆策略缺少质量约束（已修复）

#### 已确认现象

- 1、8、9 号狼人连续三轮自爆。
- 前三轮白天全部在警长竞选过程中结束，没有普通辩论和放逐。
- 项目现有评估逻辑已将三轮内三次自爆定义为 `chain_self_explosion_overuse`。

#### 影响

- 狼队用三张狼人换取连续夜刀并阻断白天信息，形成对当前 Prompt 和屠边规则的策略利用。
- 合法但极端重复，显著降低互动和观赏性。
- 警长竞选被连续重启，计算和时长被大量消耗。

#### 修改方向

不建议直接篡改已发布规则快照。应分两层处理：

1. AI 决策质量层：
   - 连续自爆必须说明可验证的阵营收益；
   - 将已有自爆次数、剩余狼数、下一夜可获得的收益和暴露最后隐狼风险加入决策；
   - 对第三次连续自爆提高“不自爆”基线，除非能直接创造胜势。
2. 可配置规则层：
   - 如果产品需要更稳定的观赏模式，可在新规则修订中增加连续自爆限制或首爆后警徽处理策略；
   - 不能静默改变已有修订 2 的历史语义。
3. 质量门禁：
   - 统计批量模拟中的连续三爆率；
   - 超过阈值时阻止模型/Prompt 版本发布。

#### 验收标准

- 在固定规则和多组种子回归中，连续三爆不再成为高频默认策略。
- 每次连续自爆日志均包含明确收益判断，不能只因“阻止信息形成”机械自爆。
- 历史回放继续按原规则展示，不被新策略配置重解释。

## 9. 推荐实施顺序

### 第一阶段：终局正确性和隐私边界

1. P0-03：停止公开流式输出私密总结。
2. P0-04：每次死亡或放逐后立即检查胜负，终局后停止玩家行动。
3. 增加私密总结泄密和终局后无后续请求测试。

这一步应最先落地，因为修改面相对集中，同时直接消除身份泄漏。

### 第二阶段：事实账本和中断语义

1. P0-01：补齐 PK 发言、身份声明和关键票型的长期事实。
2. P0-02：记录阶段中断、已完成发言者和待发言者。
3. P1-04：将投票资格、终局压力和中断信息注入 Prompt。
4. 增加基于本局关键路径的事实回归测试。

该阶段是角色智能质量的基础。没有稳定事实账本，继续调 Prompt 只会让模型更流畅地说错话。

### 第三阶段：Live 事件和法官播报

1. P1-01：所有警长终态发布结构化事件。
2. P1-02：补齐平安夜、PK、自爆、猎人和终局台词链。
3. P1-03：语音持久化与客户端连接解耦，补齐终局尾段。
4. 前后端围绕同一组事件契约完成联调测试。

### 第四阶段：策略与观感

1. P1-05：降低连续自爆成为默认策略的概率。
2. P2-01：阵容自动打散和质量门禁。
3. P2-02：重复发言重试和反方事实核对。
4. P2-03：离散动作 Prompt、超时和 SLO 优化。
5. P2-04、P2-05：摘要因果和动作格式容错。

### 第五阶段：质量门禁和监控

1. P3-01：扩展跨状态、事件和语音的泄密评估。
2. P3-02：接入质量、性能和语音覆盖率指标。
3. 将本局脱敏后固化为端到端回归 fixture。
