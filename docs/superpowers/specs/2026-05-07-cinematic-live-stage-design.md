# 沉浸式狼人杀观赛舞台设计方案

**日期**: 2026-05-07
**范围**: 优化 `apps/web` 中 `/games/live/:runId` 的实时观战首屏，把独立的观赛舞台和座位盘合并为参考图风格的圆桌舞台。后端事件协议不变。

## 1. 背景

当前实时观战页已经有导播节奏、观赛舞台、玩家座位盘、自动跟随、手动聚焦和事件时间线。但首屏仍然像调试后台：舞台是一张文字卡片，玩家座位盘在另一块区域里，用户需要在多个面板之间拼出“谁正在发言、谁还活着、场上局势如何”。

用户提供的参考图是一个暗夜村庄中的圆桌观赛舞台：玩家头像围绕桌面分布，当前发言者有明显高亮，死亡玩家灰阶，中心区域承担氛围和对局状态。目标是让实时观战第一眼更像一场正在进行的狼人杀，而不是事件列表。

## 2. 目标

- 将 `LiveDirectorStage` 改造成主视觉舞台：暗色背景、圆桌、中心事件区、围桌玩家头像。
- 把 `LivePlayerPanel` 的核心能力合并进舞台：玩家列表、存活状态、角色标签、自动跟随、手动选人。
- 当前发言或行动玩家头像必须有明确高亮，包含发光描边和 `发言中` 状态。
- 死亡玩家头像灰阶、降透明度，并显示死亡/出局状态。
- 保留现有导播队列、暂停/追到最新/倍速控制和右侧剧情时间线。
- 移动端优先显示舞台，再显示控制和时间线；玩家头像仍可点击。

## 3. 非目标

- 不新增后端字段或事件类型。
- 不引入真实头像资源；先用稳定的前端生成头像占位。
- 不做完整 3D 场景、Canvas 或 WebGL。
- 不重做复盘页、创建页、规则配置页。
- 不改变导播节奏算法。
- 不在本次实现中新增真实倒计时逻辑；顶部时间可显示当前回合/队列状态或简化的导播状态。

## 4. 推荐方案

采用纯 React/CSS 实现一个新的舞台式组件结构，避免引入新依赖：

```text
LiveGamePage
  events -> deriveLiveSpectatorState(events)
  events -> useLiveDirector(events)
  -> LiveDirectorStage
       cue
       players
       activePlayerName
       focusedPlayerName
       autoFollow
       onSelectPlayer
       onAutoFollowChange
  -> LiveDirectorControls
  -> LiveEventTimeline
```

`LiveDirectorStage` 从文字卡片升级为包含座位环的舞台。旧 `LivePlayerPanel` 可以保留文件以减少风险，但不再作为 live 页面主布局的一栏使用。

## 5. 视觉结构

桌面端首屏使用两列布局：

```text
+--------------------------------------------------+----------------------+
| 沉浸式圆桌舞台                                    | 剧情时间线            |
|  - 顶部状态胶囊 / 回合阶段 / 队列                 | 关键阶段、行动和结算   |
|  - 玩家头像围绕圆桌                               | 调试事件折叠          |
|  - 中心狼徽、事件标题、事件正文                   |                      |
|  - 底部自动跟随和当前关注摘要                     |                      |
+--------------------------------------------------+----------------------+
| 观赛节奏控制                                      |
+--------------------------------------------------+
```

移动端改为纵向堆叠：

```text
状态条
规则摘要
圆桌舞台
观赛节奏控制
剧情时间线
```

舞台背景使用 CSS 渐变塑造夜色村庄和桌面氛围。中心桌面使用椭圆、内阴影、细边框和低透明狼徽。玩家头像使用圆形按钮围绕舞台定位，支持 8 到 12 人；12 人时按参考图环绕分布。

## 6. 玩家头像规则

每个玩家座位展示：

- 座位号。
- 生成头像占位：根据姓名生成稳定背景和首字/短名。
- 玩家名。
- 角色标签。
- 存活/死亡状态。
- 如果是当前发言或行动玩家，显示 `发言中` 或行动状态，并增加金色/绿色发光描边。

角色视觉：

- 狼人：红色描边和红色角色标签。
- 预言家：金色或琥珀描边。
- 女巫：紫色标签。
- 守卫/医生：蓝绿色标签。
- 猎人：蓝色标签。
- 白痴/村民：灰色或中性色标签。

死亡视觉：

- 头像灰阶。
- 透明度降低。
- 状态显示 `死亡` 或 `出局`。
- 不再使用发言高亮，即使历史焦点仍停留在该玩家。

## 7. 交互规则

- 默认自动跟随开启，最新 actor 或导播 cue 的 actor 成为高亮玩家。
- 用户点击头像后关闭自动跟随，并把焦点固定到该玩家。
- 用户重新开启自动跟随后，焦点回到当前 actor。
- 当前 actor 到来时：
  - 对应头像发光高亮。
  - 中心事件区展示导播 cue 标题和内容。
  - 底部关注摘要展示玩家最近行动。
- 没有 cue 或没有玩家时，舞台显示等待状态，但仍保持暗色圆桌框架，避免页面闪成空白。

## 8. 组件边界

`LiveGamePage` 负责：

- 计算 `spectatorState`。
- 计算 `director`。
- 管理 `autoFollow` 和 `manualFocusName`。
- 将玩家、焦点、导播 cue 和交互 handler 传给舞台。
- 保留控制条和时间线。

`LiveDirectorStage` 负责：

- 舞台布局和视觉。
- 玩家头像座位环。
- 中心事件内容。
- 自动跟随开关入口。
- 点击头像触发 `onSelectPlayer`。

辅助函数可放在 `LiveDirectorStage.tsx` 内部，除非文件过大再拆出：

- `seatPosition(index, total)`：返回座位定位 class/style。
- `roleTone(role)`：返回角色颜色语义。
- `avatarSeed(name)`：返回稳定头像色。
- `stageTone(cue)`：返回夜晚、投票、关键事件、终局的舞台强调色。

## 9. 测试策略

更新现有前端测试，重点覆盖用户可见行为：

- live 页面仍显示 `观赛舞台` 和 `剧情时间线`。
- 玩家姓名出现在舞台座位头像中。
- 当前 actor 对应座位有可访问的发言/行动高亮信息。
- 死亡玩家显示出局状态。
- 点击玩家头像会关闭自动跟随并固定关注玩家。

验证命令：

```bash
cd apps/web && pnpm test -- --run
cd apps/web && pnpm build
```

## 10. 实施顺序

1. 扩展 `LiveDirectorStage` props，让它接收玩家列表、焦点和交互 handler。
2. 在 `LiveGamePage` 中移除三栏里的独立 `LivePlayerPanel`，改成舞台 + 控制 + 时间线布局。
3. 重写 `LiveDirectorStage` JSX 和 Tailwind class，实现圆桌、头像环、中心事件区和底部状态。
4. 更新页面测试以匹配新舞台语义和交互。
5. 运行前端测试和构建，使用本地浏览器查看 `/games/live/run_28148690ed8d`。
