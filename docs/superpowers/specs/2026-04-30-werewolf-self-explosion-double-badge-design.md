# 狼人自爆与双爆吞警徽设计

## 背景

12 人预女猎白局已经有完整警长竞选流程、警徽 1.5 票、死亡警长警徽处理和前端警长竞选展示。当前缺少狼人白天自爆能力，也无法表达“自爆直接入夜”和“双爆吞警徽”的规则。

网上资料显示，自爆吞警徽常见有单爆和双爆两类口径。单爆对狼队更友好，一狼即可让警徽流失；双爆提高了吞警徽成本，狼队必须连续投入两狼才能阻止警徽落地，更适合本项目当前偏标准、偏观战公平的 12 人局。

## 目标

- 支持狼人白天公开阶段自爆。
- 自爆狼人立刻出局并公开为狼人。
- 自爆后当天直接结束，跳过后续发言、投票和总结，进入下一夜。
- 采用双爆吞警徽：警长产生前第一次自爆只中断警长竞选，第二次自爆才让警徽流失。
- 警长已经产生后，自爆不再“吞警徽”；若自爆者本人是警长，则按现有死亡警长规则处理警徽移交或撕毁。
- 前端能清楚展示自爆事件、当天为何提前结束、警徽是否因双爆流失。

## 非目标

- 不实现单爆吞警徽作为默认规则。
- 不实现自爆吞毒、吞女巫毒药或其它特殊比赛变体。
- 不引入狼王、白狼王等额外狼人阵营角色。
- 不改变夜晚刀人、预言家查验、女巫、猎人、白痴和屠边胜利条件。
- 不把自爆做成玩家手动按钮；本项目仍由模型通过动作决策驱动。

## 规则口径

### 自爆时机

狼人可在白天公开流程中获得自爆机会：

- 警长竞选阶段：警上发言、退水、警下投票前、PK 发言、二轮投票前。
- 正式白天发言阶段：每名玩家发言前。

狼人不能在以下阶段自爆：

- 夜晚行动阶段。
- 放逐投票已经开始后。
- 猎人开枪阶段。
- 警徽移交或撕毁阶段。
- 游戏已经判定胜负后。

实现上使用统一的“自爆中断钩子”，在可中断阶段前按当前存活狼人座次询问是否自爆。第一个选择自爆的狼人立即结算，后续该阶段动作不再继续。

### 自爆结算

当狼人自爆：

1. 记录 `werewolf_self_explosion` 行动日志。
2. 将自爆者加入本轮 `day_deaths`，死亡原因 `werewolf_self_explosion`，来源为自爆者自己。
3. 将自爆者从当前存活玩家中移除。
4. 向所有玩家公告“某玩家自爆为狼人，白天立即结束。”
5. 若自爆者是猎人，不触发猎人开枪；普通狼人没有猎人能力，此处只是防御性规则。
6. 若自爆者是当前警长，走现有死亡警长警徽处理。
7. 检查胜负；若未结束，跳过当天剩余白天流程，进入下一夜。

如果首日警长竞选发生在首夜死讯公布前，自爆后仍需要先公布并结算首夜 pending 死亡，再进入下一夜。若同一玩家既自爆又在 pending 死亡名单中，只记录自爆死亡，避免同一玩家重复死亡；不额外实现“吞毒”收益。

### 双爆吞警徽

警长产生前的自爆计入警徽前自爆次数：

- 第一次：警徽不流失；本日白天结束；游戏状态标记警长竞选仍待完成。
- 第二次：警徽流失；本日白天结束；本局之后不再产生警长。

第一次自爆后的下一天，如果游戏尚未结束且没有警长、警徽也没有流失，则重新开启警长竞选。为降低跨回合状态复杂度，第二天重新组织完整警长竞选，不保留首日未完成竞选的候选、退水或投票状态；首日已公开发言仍留在回放中作为历史信息。

如果警长已经产生：

- 后续狼人自爆只结束当天。
- 不增加警徽前自爆次数。
- 不造成警徽流失。
- 若自爆者不是警长，现有警徽保持不变。
- 若自爆者是警长，按死亡警长处理，可移交或撕毁。

### 当天跳过内容

自爆后当天跳过：

- 未完成的警长竞选动作。
- 正式白天发言。
- 放逐投票。
- 回合总结模型动作。

回放中保留一个系统性说明：当天因狼人自爆提前结束。

## 后端设计

### 规则配置

在 `RuleSet` 增加自爆相关配置：

- `werewolf_self_explosion_enabled: bool`
- `sheriff_badge_bomb_policy: "none" | "double"`

12 人预女猎白局默认：

- `werewolf_self_explosion_enabled=True`
- `sheriff_badge_bomb_policy="double"`

少人局默认关闭自爆，避免扩大本次变更范围。

### 状态字段

在 `GameState` 增加：

- `sheriff_pre_election_bomb_count: int`
- `sheriff_election_pending: bool`

在 `RoundState` 增加：

- `werewolf_self_exploded: str | None`
- `day_ended_by_self_explosion: bool`
- `sheriff_pre_election_bomb_count: int`
- `sheriff_election_pending: bool`
- `sheriff_badge_lost_reason: str | None`

这些字段随 checkpoint 和 API 输出序列化，前端旧数据缺字段时用空值兜底。

### 日志字段

在 `RoundLog` 增加：

- `werewolf_self_explosion: ActionLog | None`

在 prompt/action 元数据增加：

- action: `werewolf_self_explosion`
- result field: `self_explode`
- options: `自爆`、`不自爆`

### 引擎流程

新增统一方法：

- `_maybe_run_werewolf_self_explosion(round_state, round_log, active_players, stage) -> bool`

返回 `True` 表示已经自爆并中断当天。

接入点：

- 警上发言前。
- 退水阶段前。
- 警下投票前。
- PK 发言前。
- 二轮投票前。
- 正式白天每名玩家发言前。

自爆中断后，`_run_day_phase` 负责：

1. 如有首夜 pending 死亡，公布并结算。
2. 发布 `state_updated` 事件。
3. 判断胜负。
4. 不再调用放逐投票和总结。

警长竞选入口从“只在第 1 天运行”改为：

- 规则启用警长。
- 当前没有警长。
- 警徽未流失。
- 当前是第 1 天，或 `state.sheriff_election_pending` 为真。

### Prompt 设计

`werewolf_self_explosion` prompt 只发给存活狼人。上下文包含：

- 当前阶段。
- 是否已有警长。
- 当前警徽前自爆次数。
- 若警长尚未产生，说明双爆规则：第一次只中断竞选，第二次警徽流失。
- 自爆会公开自己是狼人，并让当天直接结束。

输出字段：

```json
{"reasoning": "策略判断", "self_explode": "自爆"}
```

或：

```json
{"reasoning": "策略判断", "self_explode": "不自爆"}
```

## 前端设计

### 类型与 Adapter

`types.ts` 和 adapter 增加自爆字段兜底：

- `werewolf_self_exploded`
- `day_ended_by_self_explosion`
- `sheriff_pre_election_bomb_count`
- `sheriff_election_pending`
- `sheriff_badge_lost_reason`

debug 行动卡标题：

- `werewolf_self_explosion`: `狼人自爆`

### 回放展示

`DayPhase` 或警长竞选区块中展示：

- “某玩家自爆为狼人，白天提前结束。”
- 如果是警长产生前第一次自爆：“首爆中断警长竞选，下一天继续竞选。”
- 如果是警长产生前第二次自爆：“双爆吞警徽，警徽流失。”
- 如果自爆发生在警长产生后：“自爆结束白天，警徽状态按现有规则处理。”

`SheriffElectionPanel` 在警徽状态里展示 `sheriff_badge_lost_reason`，避免把双爆吞警徽和平票流失、无人上警混在一起。

## 测试计划

### 后端

- 规则集包含自爆配置，少人局默认关闭。
- prompt 支持 `werewolf_self_explosion` schema 和中文指令。
- 警长产生前第一次狼人自爆：
  - 自爆者死亡。
  - 当天跳过剩余警长流程、发言、投票、总结。
  - 警徽不流失。
  - `sheriff_election_pending=True`。
- 第二天继续警长竞选并可正常产生警长。
- 第二次警长产生前自爆：
  - 警徽流失。
  - 不再进入警长竞选。
- 警长产生后狼人自爆：
  - 当天结束。
  - 不改变已有警长。
- 狼人警长自爆：
  - 自爆者死亡。
  - 触发现有警徽移交或撕毁。
- 首夜 pending 死亡未公布时自爆：
  - 自爆后仍公布 pending 死亡。
  - 不重复记录同一玩家死亡。

### 前端

- adapter 正常化新增字段。
- debug 面板显示“狼人自爆”行动卡。
- 警长竞选面板显示首爆中断、双爆吞警徽、警徽流失原因。
- 自爆提前结束的白天不要求投票表或总结存在。
- 旧回放缺少新增字段时不报错。

## 风险与缓解

- 自爆钩子可能增加模型调用次数：只在 12 人局启用，并按阶段边界调用，不在每个内部工具函数里重复调用。
- 跨回合继续警长竞选容易复杂：第一版采用第二天重新竞选，保留历史发言但不保留未完成状态。
- 自爆与首夜 pending 死亡有边界情况：第一版明确不做自爆吞毒，只做去重死亡记录。
- 自爆跳过总结可能让回放少一段文本：通过系统性状态字段和前端说明补足。
