# 手机端大厅座位触发卡牌库设计

**日期**: 2026-06-20
**状态**: 已确认
**范围**: 修改 `apps/mobile-web` 的 `/games` 大厅页，使手机端大厅参考用户提供的暗夜哥特大厅图，并采用“点击座位后拉起玩家卡牌库”的交互。

## 1. 结论

采用“暗夜城堡大厅 + 座位触发卡牌库抽屉”方案。

手机端大厅首屏展示品牌标题、规则选择、组建阵容和底部开局操作。用户点击某个座位后，页面从底部拉起“玩家卡牌库”抽屉；抽屉中展示当前座位、搜索/筛选、玩家卡片、选中态和确认按钮。确认后才把玩家写入座位，降低误触。

现有创建对局逻辑不变：规则列表、玩家档案、随机补齐、只用收藏补齐、清空阵容、种子、最大轮数和发起对局继续沿用当前 `GamesPage` 的状态与 `@werewolf-arena/game-client` 辅助函数。

## 2. 背景

当前 `apps/mobile-web/src/pages/GamesPage.tsx` 是一个轻量纵向表单：

- 顶部标题为“移动大厅”。
- 规则是简单 radio 卡片列表。
- 席位是 2 列按钮网格。
- 玩家库是按钮流，点击即写入当前座位。
- 底部固定操作栏提供随机补齐、收藏补齐、清空席位和发起对局。

用户提供两张参考图：

- 图 1：完整大厅页面，包含标题、规则卡、阵容座位、玩家卡牌库、当前座位和底部导航。
- 图 2：更适合手机的结构，规则和座位在上方，玩家卡牌库作为底部大面板。

用户确认采用方案 2：座位触发卡牌库抽屉。也就是说卡牌库不默认占据半屏，而是在选座时出现。

## 3. 目标

- 让 `/games` 手机端大厅明显接近参考图的暗夜、月光、城堡、金色哥特边框风格。
- 保持手机竖屏体验，避免桌面三栏直接压缩到移动端。
- 点击座位后打开底部玩家卡牌库抽屉。
- 玩家选择需要显式确认，避免误触直接覆盖座位。
- 玩家卡片展示头像、名称、策略/类型标签、收藏状态和选中状态。
- 保留现有开局能力和数据流，不改 API 合约。
- 更新测试，保护原有创建对局流程和新增抽屉交互。

## 4. 非目标

- 不修改 `apps/api`。
- 不改变桌面端 `apps/web` 大厅。
- 不把桌面端 React 组件直接导入移动端。
- 不新增玩家新建、编辑、删除、头像上传或头像生成能力。
- 不做拖拽换座。
- 不实现与玩家档案字段无关的假筛选。参考图中的“阵营/类型”视觉可以保留，但筛选项必须来自现有可用字段，例如收藏、策略、个性或标签。
- 不优先处理横屏和平板复杂布局；大屏继续居中展示手机宽度。

## 5. 页面结构

`GamesPage` 仍是单页面创建对局工作台，但结构重组为四块：

1. 大厅头部
   - 展示徽记感标题“狼人杀对局大厅”。
   - 展示短副标题“公平 · 推理 · 社交的暗夜决策”。
   - 使用暗夜城堡背景、月光、薄雾和金色文字层次。

2. 规则选择
   - 横向规则卡片列表，支持滑动。
   - 每张规则卡显示规则名、人数、角色摘要和 2 到 3 个短标签。
   - 选中规则使用金色描边、发光和角标。
   - 保留加载失败和加载中状态。

3. 组建阵容
   - 展示当前规则名和座位数量。
   - 座位使用紧凑哥特卡片网格，8 人局为两行四列；更小宽度允许横向滚动或两列自适应。
   - 座位卡显示座位号、头像占位/已选头像、玩家名或“待选择”。
   - 点击座位设置 `activeSeat`，并打开玩家卡牌库抽屉。

4. 开局操作区
   - 保留种子和最大轮数输入。
   - 保留随机补齐、只用收藏补齐、清空阵容和发起对局。
   - 主按钮“发起对局”保持最醒目。
   - 错误提示显示在页面内容区顶部，不藏在抽屉里。

## 6. 玩家卡牌库抽屉

新增局部状态：

```ts
const [isProfileDrawerOpen, setIsProfileDrawerOpen] = useState(false);
const [pendingProfileId, setPendingProfileId] = useState<string | null>(null);
const [profileSearch, setProfileSearch] = useState("");
const [profileStrategyFilter, setProfileStrategyFilter] = useState("all");
```

打开方式：

- 点击座位按钮。
- 设置当前座位为被点击座位。
- 将 `pendingProfileId` 初始化为该座位当前已选玩家。
- 打开抽屉。

抽屉内容：

- 顶部拖拽柄、标题“玩家卡牌库”、关闭按钮。
- 当前选择提示，例如“当前选择：1号座位”。
- 搜索框，按名称、标签、模型、短描述等已有字段过滤。
- 筛选控件：
  - 收藏/全部。
  - 策略类型，来自 `strategy_profile` 的实际值。
  - 标签或个性字段如果数据足够稳定，可作为后续增强；第一版不硬造阵营筛选。
- 玩家卡片网格。
  - 头像：优先 `avatar_image_url`，否则使用暗色头像占位。
  - 标题：`display_name`。
  - 副信息：策略、模型或个性。
  - 收藏星标。
  - 选中状态：金色描边和勾选徽记。
- 底部“确认选择”按钮。

确认行为：

- 点击玩家卡片只更新 `pendingProfileId`。
- 点击“确认选择”后调用现有 `assignProfileToActiveSeat` 逻辑，把玩家写入 `safeActiveSeat`。
- 确认后关闭抽屉。
- 关闭抽屉不修改座位。

空状态：

- 玩家库加载失败：显示“玩家库加载失败”。
- 没有匹配玩家：显示空状态。
- 玩家库为空：保留可用提示，并继续允许随机补齐触发不足提示。

## 7. 数据流

沿用现有查询：

- `listRuleSets`
- `listPlayerProfiles`
- `createGameRun`

沿用现有派生：

- `selectedRuleSet`
- `visiblePlayerConfigs`
- `selectedProfilesBySeat`
- `safeActiveSeat`
- `isSubmitDisabled`

新增派生：

- `activeSeatProfile`
- `filteredProfiles`
- `strategyFilterOptions`

`handleRuleSetChange` 继续负责规则切换后的座位数量调整。若规则切换导致当前座位变化，抽屉仍以 `safeActiveSeat` 为准；如果玩家库抽屉已打开，可以保持打开并更新当前座位提示。

`upsertSeatProfile` 继续保证同一个 profile 不会被分配到多个座位。

## 8. 视觉设计

整体风格：

- 深黑、冷蓝、暗金为主。
- 使用城堡夜空、月亮、雾气、金色细边、尖角和徽记感。
- 避免一整页只靠单色深蓝，规则卡和玩家卡通过金色、紫色、绿灰和冷白头像层次区分。

资产策略：

- `apps/mobile-web` 保持独立资源边界。
- 可以在 `apps/mobile-web/src/assets/lobby/` 下放置移动端自有大厅背景和必要装饰图。
- 可从 `apps/web/src/assets` 复制稳定的城堡背景、规则卡或边框资源作为移动端资产副本，但不从 mobile 直接跨 app import 桌面端源码。
- 若本轮实现不需要完整图片切片，可先用 CSS 渐变、背景图和伪元素完成暗夜大厅视觉，再保留后续替换资产的空间。

移动布局：

- `mobile-page` 在大厅页增加专用 class，例如 `mobile-lobby-page`，避免影响玩家页、历史页、直播页和复盘页。
- 规则卡横向滚动，卡片宽度固定在手机可读范围。
- 座位格使用稳定高度，避免头像或长名字导致布局跳动。
- 抽屉使用 fixed 定位，底部避开 `env(safe-area-inset-bottom)` 和已有 tab bar。
- 抽屉打开时添加半透明遮罩，点击遮罩关闭。

## 9. 可访问性与移动交互

- 座位按钮保留 `aria-pressed`，并增加清晰的可访问名称，例如“选择 1 号座位，当前为暗巷斯场”。
- 抽屉使用 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`。
- 关闭按钮有可访问名称。
- 玩家卡片按钮有可访问名称，例如“为 1 号座位候选 暗巷斯场”。
- 确认按钮在没有候选玩家时禁用。
- 输入框和筛选控件使用真实 label 或 `aria-label`。
- 不依赖 hover。

## 10. 错误处理

保留现有错误面：

- 最大轮数不合法：页面顶部 `role="alert"`。
- 玩家库不足：页面顶部 `role="alert"`。
- 创建失败：页面顶部 `role="alert"`。
- 规则加载失败：规则区显示失败提示。
- 玩家库加载失败：抽屉和页面可见位置都能提示。

抽屉错误不阻止用户使用随机补齐或清空席位。

## 12. 风险与缓解

- 抽屉与底部 tab bar 重叠：抽屉底部 padding 使用 `calc(72px + env(safe-area-inset-bottom))` 或等效安全区。
- 玩家头像缺失导致卡片单调：提供稳定的暗色头像占位和徽记。
- 筛选字段不足：第一版只实现真实可用字段，避免假控件。
- CSS 影响其他移动页面：大厅专用样式全部挂在 `.mobile-lobby-page` 下。
- 视觉资源跨 app 引用脆弱：移动端使用自有资产副本或 CSS，不直接引用 `apps/web/src`。
