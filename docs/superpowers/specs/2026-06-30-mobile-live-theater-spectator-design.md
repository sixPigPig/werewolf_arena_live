# 移动观战页剧场化改造设计

**日期**: 2026-06-30
**状态**: 已确认
**范围**: 仅修改 `apps/mobile-web` 的 `/games/:gameId/live` 实时观战页。参考用户提供的竖屏狼人杀观战截图，将当前信息卡片流改造成全屏剧场式观战页。后端事件协议、共享推导逻辑和桌面端页面不在本次范围内。

## 1. 背景

当前移动观战页已经接入实时 run 查询、SSE 事件、导播节奏、`deriveLiveSpectatorState` 和 `deriveGodViewState`。页面结构仍是常规移动信息流：顶部标题、概要卡片、当前事件卡片、两列玩家卡片和固定操作条。

用户提供的参考图是手游式观战界面：顶部帷幕和状态、左右两列玩家圆头像、中心舞台、底部当前发言条和互动按钮。用户确认采用“均衡舞台化”方向：画面接近参考图，但保留观战页已有的暂停、倍速、追到最新、失败继续和查看复盘能力。用户还确认直播页隐藏底部主导航，使用顶部返回。

## 2. 目标

- 将移动实时观战首屏改为全屏沉浸式舞台。
- 隐藏直播页底部主导航，避免压缩舞台空间。
- 顶部提供返回按钮、规则名、连接状态和当前导播状态。
- 中上部展示圆形天幕、当前天数/轮次和阶段横幅。
- 左右两列展示玩家圆形座位头像，支持 6、8、12 人的稳定排列。
- 中心区域展示当前发言或行动玩家，并保留当前事件信息。
- 底部展示当前关注玩家和观战操作：暂停/继续、1x/2x、追到最新、失败继续、查看复盘。
- 玩家死亡或出局时灰阶、降透明度；当前发言或行动玩家使用绿色/金色高亮。
- 保持现有数据来源和业务语义，不新增后端字段。

## 3. 非目标

- 不修改 `apps/api`。
- 不修改 `packages/game-client` 的事件协议或推导逻辑。
- 不修改桌面端 `apps/web` 的观战页。
- 不新增真实 3D 场景、Canvas 或 WebGL。
- 不新增礼物、道具、付费金币等非观战功能。
- 不实现真实倒计时；先展示现有 `godViewState.countdownLabel` 或导播状态文案。

## 4. 推荐方案

采用移动端页面内重组 + CSS 舞台化的方案。`LivePage` 继续负责数据查询、事件连接、导播控制和恢复逻辑，但将原来的概要卡、当前事件卡、玩家网格和操作条重组为一个全屏 `mobile-live-stage`。

页面结构建议：

```text
+------------------------------------------------+
| 顶部返回 | 规则名 / 状态 | 连接状态           |
|------------------------------------------------|
| 帷幕 / 天幕 / 第 N 天 / 阶段                   |
|                                                |
| 左侧玩家列       中心当前行动者       右侧玩家列 |
|                                                |
|              当前事件 / 阶段摘要               |
|------------------------------------------------|
| 当前关注玩家条                                 |
| 暂停/继续  1x/2x  追到最新  继续对局/复盘       |
+------------------------------------------------+
```

`LivePage` 可拆出几个本地子组件，保持文件可读：

- `LiveTheaterTopBar`: 顶部返回、规则、连接、导播状态。
- `LiveSkyBanner`: 圆形天幕和天数/阶段。
- `LiveSeatColumn` / `LiveSeatAvatar`: 左右座位列和单个玩家头像。
- `LiveCenterStage`: 当前发言者、当前事件、阵营/身份简要状态。
- `LiveTheaterControls`: 底部关注条和观战操作。

若拆分后 `LivePage.tsx` 仍可读，可先将这些子组件保留在同一文件。只有当文件过大或测试需要复用时，再移动到独立组件文件。

## 5. 数据映射

继续使用现有数据：

- `run.rule_set.name`: 顶部规则名。
- `connectionState`: 顶部连接状态。
- `liveStatus.label`: 顶部导播状态。
- `spectatorState.currentRound`: 天数/轮次。
- `spectatorState.currentPhase` 或 `godViewState.phaseLabel`: 阶段横幅。
- `godViewState.players`: 座位列表、身份、阵营、存活、发言态、状态标签。
- `godViewState.speakerFlow.current`: 优先作为当前中心玩家。
- `spectatorState.activePlayerName`: 当前行动者 fallback。
- `currentEvent`: 当前事件类型和 action。
- `godViewState.countdownLabel`: 底部状态文案。

头像规则：

- 若 `player.avatarImageUrl` 存在，使用真实头像。
- 否则生成姓名首字或座位号占位。
- 角色标签使用现有 `player.role`，展示短标签；未知角色显示“未知”。

座位排列：

- 前半玩家进入左列，后半玩家进入右列。
- 左列从上到下排列；右列从上到下排列。
- 6 人、8 人、12 人都使用同一列布局，通过 CSS clamp 控制头像尺寸和间距。

## 6. 交互

- 顶部返回按钮优先调用 `navigate(-1)`；当浏览历史不足时 fallback 到 `/games`。
- 暂停/继续调用 `director.togglePaused`。
- 1x/2x 调用现有 `director.setSpeed`。
- 追到最新调用 `director.catchUpToLatest`。
- 失败对局展示“继续对局”，沿用现有 `resumeMutation`。
- 终局或 terminal event 后展示“查看复盘”链接。
- 玩家头像本次先不新增选择详情交互；头像只承担状态展示，避免引入新的抽屉或复杂焦点状态。

## 7. 视觉规则

- 页面整体使用暗红帷幕、金色边框、青蓝天幕和暖金舞台光。
- 页面首屏占满 `100svh`，并通过 `overflow: hidden` 保持舞台感。
- 顶部导航为轻量圆形返回按钮，不显示底部主导航。
- 玩家头像固定为圆形，姓名使用短文本省略，避免在小屏溢出。
- 当前发言或行动玩家：
  - 头像加绿色或金色光圈。
  - 显示“发言中”或 `stageStatus.label`。
  - 中心舞台显示该玩家姓名和座位。
- 死亡或出局玩家：
  - 头像灰阶。
  - 降低透明度。
  - 状态显示“出局”或现有 `stageStatus.label`。
- 操作按钮使用圆形或胶囊按钮，文字保持短：暂停、继续、1x、2x、最新、复盘。

## 8. 可访问性与响应式

- 主区域保留 `main` 语义，顶部返回按钮有明确 `aria-label`。
- 玩家座位区保留 `aria-label="玩家席位"`。
- 操作区保留 `aria-label="实时观战操作"`。
- 文字不依赖负 letter-spacing，不用 viewport width 缩放字体。
- 关键容器用 `minmax`、`clamp`、固定 `aspect-ratio` 和 `overflow: hidden` 避免布局跳动。
- 小于 360px 宽时，头像和姓名字号收紧，但仍保留左右列结构。

## 9. 测试策略

更新移动端测试：

- `LivePage` 仍按 `/games/:gameId/live` 调用 `getGameRun` 和 `useGameRunEvents`。
- 页面展示规则名和连接状态。
- 页面展示顶部返回按钮。
- 玩家席位以圆形座位形式渲染，至少包含玩家姓名和座位号。
- 当前事件仍展示 `game_started` 或对应事件类型。
- 样式中有隐藏底部主导航的直播页规则，避免沉浸页被底部导航占位。

验证命令：

```bash
pnpm test:mobile
pnpm build:mobile
```

视觉验证：

- 启动 `pnpm dev:mobile`。
- 用 375 x 812 视口检查 `/games/:gameId/live`。
- 确认首屏不出现底部主导航，顶部返回可见，左右座位和底部操作不重叠。

## 10. 实施顺序

1. 更新 `LivePage.test.tsx`，先覆盖新舞台语义和顶部返回。
2. 重组 `LivePage.tsx` JSX，新增剧场化子组件和必要的辅助函数。
3. 在 `index.css` 中替换或扩展 `.mobile-live-*` 样式，实现全屏舞台、隐藏底部导航和响应式座位列。
4. 运行移动端测试，修复断言或可访问性问题。
5. 运行移动端构建。
6. 启动本地移动端开发服务器并做 375 x 812 视觉检查。
