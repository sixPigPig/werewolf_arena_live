# 大厅页横向控制台改版设计

## 目标

将大厅页改成更接近参考图的横向哥特控制台：顶部是一条紧凑的创建对局控制栏，下方是横排官方规则卡片，已选规则详情继续保留在规则卡片区下方。

这次改版只调整大厅页的视觉层级、布局和局部组件结构，不改变发起对局 API、规则集数据模型、导航体系、直播跳转或历史页。

## 当前上下文

大厅页入口是 `GamesPage`，它渲染 `ArenaGlobalNav` 和 `GamesWorkspace`。`GamesWorkspace` 负责页面主体标题与创建表单。实际创建逻辑集中在 `CreateGameRunForm`：

- `useQuery(["rule-sets"])` 读取官方规则。
- `selectedRuleSetId` 控制规则卡选中状态。
- `seed`、`maxRounds`、`eventPacing` 控制顶部参数。
- `createGameRun` 成功后跳转 `/games/live/:runId`。
- `SelectedRuleDetails` 展示已选规则的完整说明。

现有测试已经覆盖规则卡渲染、选中规则详情、参数提交、最大轮数校验和导航行为。改版应保留这些行为。

## 推荐方案

采用结构微调加 CSS 强化。

`CreateGameRunForm` 继续是唯一的创建表单，但内部布局调整为：

1. 顶部控制台
   - 左侧显示大厅标题“狼人杀对局大厅”。
   - 中间依次放置“随机种子”“最大轮数”控件。
   - 右侧放置哥特风“发起对局”按钮。
   - 面板使用暗色半透明底、金色细边、内框线和角标，形成参考图里的游戏 UI 控制条。

2. 官方规则面板
   - 独立的边框面板包住 legend 与规则卡片。
   - legend 保留菱形标识和“官方规则”文本。
   - 规则卡宽屏四列，中屏两列，移动端一列。
   - 卡片内容更紧凑：左侧为圆形纹章，右侧为规则名、人数/复杂度/时长、阵营配置和标签。
   - 选中态使用金色边线与微光，悬浮态只增强边线和亮度。

3. 规则详情区
   - `SelectedRuleDetails` 保留在规则卡片下方。
   - 它继续显示阵营配置、发言顺序、警长规则、胜利条件和复盘提示。
   - 视觉上可以沿用同一套边框面板语言，但不折叠、不移除。

这种方案能最大程度复用已有逻辑和测试，同时让首屏形态贴近参考图。

## 组件边界

`GamesWorkspace` 负责页面外层宽度和锚点，不再单独渲染页面标题。标题移动到 `CreateGameRunForm` 顶部控制台内，这样截图中的标题和创建参数能处在同一个面板。

`CreateGameRunForm` 负责：

- 渲染顶部控制台。
- 渲染官方规则面板。
- 渲染已选规则详情。
- 保持原有提交、校验和错误提示。

新增的样式类放在 `apps/web/src/styles/index.css`，命名使用 `lobby-console-*` 或 `lobby-rule-*` 前缀，避免污染历史页和直播页样式。通用 `Button` 和 `ArenaNavButton` 不改。

## 响应式规则

桌面宽屏：

- 页面主体使用接近全宽的约束宽度，保留左右安全边距。
- 顶部控制台单行排列。
- 官方规则卡片四列排列，卡片高度稳定。

中等宽度：

- 顶部控制台允许参数区换行，但标题仍在第一行左侧。
- 规则卡片两列。

移动端：

- 顶部控制台改为纵向堆叠。
- 每个表单控件撑满宽度。
- 规则卡片一列。
- 文字保持正常字号，不用 viewport 字体缩放。

## 数据流

数据流不变：

1. 页面加载后请求 `/api/v1/games/rule-sets`。
2. 规则卡使用 `selectedRuleSetId` 控制选中态。
3. 详情区根据 `selectedRuleSet` 渲染。
4. 提交时解析 `maxRounds`，失败显示现有校验错误。
5. 成功创建后跳转到实时观战页。

## 错误处理

保留现有错误处理：

- 规则列表加载中显示“正在读取官方规则...”。
- 规则列表失败显示“无法读取官方规则”。
- 最大轮数不合法显示“最大轮数必须是 1 到 20 的整数”。
- 创建失败显示“无法发起对局”。

样式改版不能隐藏这些状态，也不能让禁用态按钮看起来可点击。

## 测试计划

先用测试锁定新的结构和样式意图：

- 大厅页仍渲染 `games-workspace-module` 和 `games-create-module`。
- `games-create-module` 拥有新的顶部控制台类。
- 标题“狼人杀对局大厅”仍作为 `h1` 存在。
- 顶部控制台内包含随机种子、最大轮数和发起对局。
- 官方规则 radiogroup 仍能渲染所有规则。
- 已选规则详情仍显示在规则卡片之后。
- 发起对局提交 payload 不变。

实现后运行：

- `pnpm --dir apps/web test -- --run src/pages/GamesPage.test.tsx`
- `pnpm --dir apps/web build`

视觉验证需要启动 web 开发服务器，并用浏览器查看 `/games` 的桌面和移动宽度截图，重点检查顶部控制台是否单行紧凑、规则卡片是否横向排列、详情区是否仍在下方。

## 非目标

- 不新增或删除官方规则。
- 不改变后端接口。
- 不改变导航条。
- 不重做历史页、直播页或复盘页。
- 不把详情区折叠、移除或挪到弹窗。

## 自查

- 没有未定需求。
- 设计范围聚焦大厅页创建表单。
- 推荐方案与用户确认的“保留详情区”一致。
- 测试计划覆盖结构、行为和视觉验证。
