# 大厅页三栏组局台迭代设计

## 1. 结论

大厅页采用参考图中的横向组局台结构，在保留现有业务能力和哥特视觉体系的基础上，将页面重排为：

- 左栏选择规则。
- 中栏查看规则摘要、阵容进度并安排席位。
- 右栏搜索、筛选和选择虚拟玩家。
- 底部操作栏统一承载对局参数、阵容快捷操作和“发起对局”。
- 完整规则说明不再常驻占据首屏，通过右侧详情抽屉查看。

本轮使用现有规则集、虚拟玩家和创建对局接口，不修改后端 API 或数据模型。响应式范围包含桌面、平板和手机，不把移动端留到后续迭代。

## 2. 背景与现状

当前 `/games` 已经具备完整的组局能力：

- 选择官方规则。
- 查看规则详情。
- 查看阵容摘要。
- 选择席位和虚拟玩家。
- 搜索并按收藏、模型、性格、策略筛选玩家。
- 清空席位、随机填充、仅用收藏填充。
- 配置随机种子、最大轮数并发起对局。

目前主要问题不是能力缺失，而是信息架构仍以纵向表单为主：规则卡、完整规则、席位、玩家选择和席位详情依次向下堆叠。用户需要频繁滚动，席位与玩家库的关联不够直观，开局参数与组局操作也分散在页面上下两端。

参考图的核心价值不是单纯增加装饰，而是把“选择规则、安排阵容、选择玩家、发起对局”组织成一个同屏工作台。

## 3. 目标

### 3.1 产品目标

- 桌面首屏同时展示规则、席位和玩家库，使组局主流程无需纵向滚动。
- 强化“当前正在为哪个席位选人”的上下文。
- 将低频规则说明与高频组局操作分层，减少首屏信息噪声。
- 将开局参数、阵容快捷操作和主操作集中到统一的底部操作栏区块。
- 延续现有暗黑哥特视觉，不引入与项目不一致的新设计语言。

### 3.2 成功标准

- 用户在 `1440 × 900` 的桌面基准视口内可以完成规则选择、席位选择、玩家选择和发起对局，无需页面级纵向滚动。
- 当前规则、当前席位、已选玩家数量和主操作在任意时刻都有明确反馈。
- 桌面、平板和手机均可完整完成组局流程。
- 创建对局请求结构、校验语义和跳转行为保持兼容。

## 4. 非目标

- 不新增、删除或编辑官方规则。
- 不新增玩家图鉴、通知中心或独立设置中心。
- 不实现阵容模板保存、拖拽换座或多人在线房间。
- 不在大厅内编辑完整玩家档案；编辑仍由 `/players` 承担。
- 不修改后端创建对局、规则集或虚拟玩家接口。
- 不重做玩家库、历史页、直播页或复盘页。
- 不追求像素级复刻参考图中的全部图标和装饰。

## 5. 方案选择

### 5.1 采用方案：三栏组局台

采用“左规则、中席位、右玩家”的三栏布局，并将参数与操作统一下沉到底部操作栏。

选择理由：

- 最直接地解决当前页面过长和关联操作分散的问题。
- 可以复用现有 `SeatGrid`、`ProfilePicker`、`LineupSummary` 和组局工具函数。
- 与参考图的空间关系一致，但无需扩展无关产品模块。
- 相比单纯视觉精修，能产生明确的操作效率收益。

### 5.2 未采用方案

现状精修方案只调整卡片和边框，不改变纵向信息结构，无法解决滚动和上下文割裂问题。

高还原扩展方案会同时引入图鉴、设置、通知、分页等新模块，使本轮从大厅重排扩大为多模块产品迭代，范围和风险过高。

## 6. 页面信息架构

### 6.1 顶部导航

保留现有全局导航与品牌区域：

- 对局大厅。
- 玩家库。
- 对局历史。
- 新建对局主入口。

本轮只调整大厅主体，不改变导航路由和语义。

### 6.2 左栏：规则选择

左栏纵向展示官方规则卡。每张卡保留足够做选择判断的信息：

- 规则名。
- 玩家人数。
- 阵营或角色摘要。
- 复杂度或推荐标签。
- 选中状态。

规则卡不再承载完整规则说明。选中规则使用红铜底色、暗金描边和轻微辉光，未选中卡保持低对比度。

### 6.3 中栏：组建阵容

中栏是页面主工作区，分为三个层次：

1. 标题与进度：当前规则名、`已选 X / N`、空席数量。
2. 规则摘要：角色构成和“规则详情”入口。
3. 席位卡阵列：根据规则人数展示 6、8 或 12 个席位。

`LineupSummary` 中的模型分布、性格分布、收藏数量和异常席位提示保留，但压缩为席位区上方的次级摘要，不与规则详情竞争视觉焦点。

### 6.4 右栏：玩家卡牌库

右栏固定显示当前席位上下文和玩家选择能力：

- 当前席位编号和当前玩家。
- 搜索框。
- 收藏、模型、性格和策略筛选。
- 玩家卡片列表。
- 当前席位清空和模型覆盖。

玩家卡使用头像、名称、模型和性格作为主要识别信息。已在其他席位使用的玩家显示“已在 X 号位”并禁用，当前席位已选玩家保持高亮。

### 6.5 底部操作栏

底部操作栏位于三栏工作台下方，桌面端保持同屏可见，不使用遮挡内容的悬浮定位。

从左到右组织为：

- 随机种子。
- 最大轮数。
- 随机填充空席。
- 只用收藏填充。
- 清空阵容。
- 发起对局。

“清空当前座位”和当前席位模型覆盖仍属于右栏席位上下文，不移动到底部全局操作区。

## 7. 核心交互

### 7.1 规则选择

- 点击规则卡立即切换当前规则和席位数量。
- 从少人数规则切换到多人数规则时，保留已有有效席位配置并增加空席。
- 从多人数规则切换到少人数规则时，保留新规则人数范围内的配置，移除超出范围的席位配置。
- 如果有超出范围且已配置的席位被移除，在工作台顶部显示一次轻量状态提示，例如“已移除 9-12 号位的 3 名玩家”。
- 规则切换后当前席位若超出范围，则自动切换到新规则的最后一个席位。

### 7.2 席位与玩家选择

- 进入页面时默认选中 1 号席位。
- 点击席位卡后，右栏标题、当前玩家和操作全部切换到该席位。
- 点击可用玩家卡立即填入当前席位，不增加二次确认。
- 同一玩家不能同时占用多个席位；其他席位已使用的玩家卡禁用并标明座位。
- 点击“清空当前座位”移除当前席位的玩家和临时覆盖配置。
- 模型覆盖继续作用于当前席位，不修改玩家库中的原始档案。

### 7.3 阵容快捷操作

- “随机填充空席”只使用未被占用的玩家。
- “只用收藏填充”只使用未被占用的收藏玩家。
- “清空阵容”清空全部席位，触发前需要二次确认，避免误操作。
- 空席不是表单错误；提交时继续使用现有逻辑随机补齐。
- 如果玩家库总量不足以满足当前规则人数，沿用现有阻断对话框并引导用户前往玩家库创建玩家。

### 7.4 规则详情抽屉

中栏规则摘要右侧提供“规则详情”按钮。点击后打开工作台右侧抽屉，展示现有完整信息：

- 规则描述。
- 阵营配置。
- 发言顺序。
- 警长规则。
- 胜利条件。
- 复盘提示。

桌面和平板使用从右侧进入的覆盖式抽屉，不改变三栏宽度，不导致席位区跳动。手机使用底部全宽详情面板，避免窄屏横向挤压。

抽屉支持关闭按钮、点击遮罩关闭和 `Escape` 关闭。打开时焦点进入抽屉，关闭后返回“规则详情”按钮；抽屉内容可独立滚动。

### 7.5 发起对局

- 点击“发起对局”后先校验最大轮数。
- 对有效席位配置进行排序和规范化。
- 对空席执行现有随机填充。
- 玩家不足时显示现有不足提示，不发送创建请求。
- 创建成功后继续跳转 `/games/live/:runId`。
- 创建期间主按钮进入加载状态并禁用重复提交。

## 8. 响应式设计

断点沿用项目现有大厅样式边界，减少全局样式波动。

### 8.1 桌面：大于 1180px

- 三栏同屏，建议宽度比例为 `24% / 48% / 28%`。
- 工作台主体按导航下方的可用视口高度布局；三栏底边对齐，规则列表和玩家列表在内容溢出时独立滚动。
- 6 人和 8 人规则使用四列席位卡，12 人规则使用四列三行。
- 底部操作栏保持单行，主按钮位于最右侧。

### 8.2 平板：721px 至 1180px

- 使用双栏：左侧规则栏约 `34%`，右侧工作区约 `66%`。
- 右侧先显示规则摘要和席位，再显示玩家选择区；玩家区在右侧工作区内纵向衔接，不与规则栏争夺宽度。
- `900px` 至 `1180px` 使用四列席位卡，`721px` 至 `899px` 使用两列，不允许卡片内容溢出。
- 底部操作栏允许分为参数区和操作区两行。
- 规则详情仍使用右侧抽屉。

### 8.3 手机：不大于 720px

- 主体改为单栏，顺序为规则、规则摘要与席位、玩家选择、开局参数。
- 规则卡使用横向滚动列表，避免四张规则卡形成过长页面。
- 席位卡使用两列。
- 玩家筛选器纵向排列，玩家卡默认使用两列；不大于 `360px` 时改为单列。
- 选中席位后将玩家选择区滚动到可见范围，并在区块标题中持续显示当前席位。
- 底部操作栏改为普通文档流区块，不做固定底栏。
- 规则详情使用底部全宽面板。

## 9. 视觉语言

继续使用项目现有的暗色哥特 UI，不重新定义品牌系统。

- 背景：深蓝黑和低透明度纹理，减少大面积高亮。
- 边框：暗金细边、内框线和局部角饰。
- 选中态：红铜底色、金色描边和克制辉光。
- 玩家与席位卡：以肖像为视觉中心，文字放在卡片底部暗色渐变区。
- 主按钮：沿用红铜色哥特按钮，保证全页最高操作优先级。
- 字体：标题沿用衬线字体，表单和高密度信息继续使用现有无衬线字体。
- 动效：抽屉、卡片选中和筛选结果使用短时过渡；不增加持续闪烁或大幅位移动效。

## 10. 组件与职责

### 10.1 `CreateGameRunForm`

继续作为创建对局状态与提交入口，负责：

- 规则选择。
- 随机种子和最大轮数。
- 玩家配置状态。
- 规则切换时的席位裁剪提示。
- 提交校验、随机补齐和创建请求。
- 组合三栏工作台和底部操作栏。

### 10.2 `LobbyRuleSelector`

从当前内联规则卡渲染中提取，负责规则列表、选中态和加载/失败状态。它只上报规则 ID，不管理提交状态。

### 10.3 `LobbyLineupWorkbench`

由现有 `PlayerConfigPanel` 演进而来，负责当前席位、阵容摘要和中右栏组合。内部继续复用：

- `LineupSummary`。
- `SeatGrid`。
- `ProfilePicker`。
- `SeatDetailPanel` 的席位级能力。

`PlayerConfigPanel` 不再承担外层完整面板造型，避免三栏框架内出现重复边框和标题层级。

### 10.4 `RuleDetailsDrawer`

新增独立组件，接收当前 `RuleSetSummary`、打开状态和关闭回调。负责可访问性焦点管理、遮罩、关闭行为以及桌面抽屉/手机底部面板样式。

### 10.5 `LobbyActionBar`

新增底部操作栏组件，接收表单字段、阵容操作和提交状态。它不自行持有业务状态，避免与 `CreateGameRunForm` 产生双向同步。

## 11. 状态与数据流

现有接口和提交结构保持不变：

1. `GamesWorkspace` 读取虚拟玩家列表。
2. `CreateGameRunForm` 读取官方规则并持有 `selectedRuleSetId`、`seed`、`maxRounds` 和 `playerConfigs`。
3. 当前规则决定有效席位数量。
4. 当前席位由组局台本地状态管理，并始终限制在有效范围内。
5. 规则、席位和玩家选择更新同一份 `PlayerConfig[]`。
6. 提交前继续使用现有规范化、无效引用清理和随机填充逻辑。
7. 创建成功后沿用现有直播页跳转。

新增的纯界面状态包括：

- 规则详情抽屉是否打开。
- 规则切换后的席位裁剪提示。
- 清空阵容确认对话框是否打开。

这些状态不进入 URL、不持久化，也不改变请求数据。

## 12. 加载、空状态与错误处理

- 规则加载中：左栏显示现有“正在读取官方规则...”文案，中右栏不可操作。
- 规则加载失败：左栏显示“无法读取官方规则”，发起对局禁用。
- 玩家加载中：右栏显示加载状态，规则与席位仍可查看，发起对局保持现有禁用语义。
- 玩家库为空：右栏显示空状态和“去玩家库创建”。
- 玩家筛选无结果：保留筛选控件并显示“没有符合条件的虚拟玩家”。
- 玩家引用失效：席位显示异常态，提交前继续清理无效引用。
- 最大轮数不合法：在底部参数区附近显示现有校验文案。
- 创建失败：在底部操作栏上方显示“无法发起对局”。
- 玩家不足：继续使用现有模态对话框，不被规则抽屉遮挡。

## 13. 可访问性

- 规则列表继续使用单选组语义。
- 席位和玩家卡保持真实 `button`，可通过键盘聚焦和操作。
- 当前席位、规则选中态和收藏筛选状态需要有非颜色反馈。
- 禁用玩家卡保留“已在 X 号位”的可读说明。
- 规则抽屉使用 `dialog` 语义、可访问名称和焦点圈定。
- 清空阵容确认框使用 `alertdialog` 或等价确认语义。
- 移动端横向规则列表保留键盘和触控滚动能力。
- 交互控件保持项目现有最小点击尺寸和可见焦点样式。

## 15. 验收标准

- 在 `1440 × 900` 基准视口进入 `/games` 后，规则、席位、玩家库和发起对局在首屏可见，页面主体不产生纵向滚动。
- 规则选择位于左栏，席位位于中栏，玩家选择位于右栏。
- 完整规则通过详情抽屉展示，不再作为常驻纵向大区块。
- 所有现有规则均可正确生成对应数量的席位。
- 用户可以选择席位、选择玩家、筛选玩家、清空和填充阵容并成功发起对局。
- 重复玩家选择、玩家不足、无效最大轮数和接口失败均有明确反馈。
- 1024px 与 390px 宽度下可以不依赖桌面布局完成全部流程。
- 后端 API、创建请求字段和直播页跳转保持不变。
- 页面测试、相关工具函数测试和 Web 构建通过。
